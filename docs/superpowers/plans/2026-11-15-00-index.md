## Order

1. **Plan 01** first. Its lanes A–D run in parallel; Task 17 (lane E) runs after the four lanes are merged. Plan 01 lane A must be merged before plans 03–05 start, because all three add sections to the collector and use the Node harness.
2. **Plans 02, 03, 04, 05** can then run in parallel, one agent (or one agent team) each, each in its own worktree.
3. Three small follow-ups connect the feature plans. Each is listed in the "Final gate" of its plan and is done by whichever lands second:
   - 03 → 02: summary rules `permission-request`, `third-party-device-access`.
   - 04 → 02: summary rules `technique-<id>`; batch option `freshLoad` already exists.
   - 05 → 02: summary rule `third-party-area`.

## Rules for every agent

- Read the plan's header (Global Constraints, Review Focus) and the spec before the first task.
- Test first, see it fail, then implement; one commit per task; never push.
- `flutter analyze --no-pub && flutter test` must be clean before a task is reported done. Report the command output, not a summary of it.
- A step that says "check … before coding" is a real step: if the check contradicts the plan, stop and report it instead of following the plan.
- Steps marked as a real-browser gate or real check need macOS with a display. An agent without one reports the gate as not run; it does not mark it passed.
- Do not touch `docs/superpowers/plans/2026-11-06-centraal-datapunt-tests.md` or the two November audit documents.

## Decisions the owner should confirm before execution

These are choices the plans make that have no external norm. Changing one changes a constant or a rule, not the structure.

1. Plan 01 Task 2: a document sized from the app's own request now counts as an **estimate** (shows `≈`), where it counted as measured.
2. Plan 01 Task 4: on iOS/macOS the collector moves to an isolated world and the fetch/XHR size patch is dropped there. Cross-origin fetch/XHR sizes without Timing-Allow-Origin become "unknown" on those platforms.
3. Plan 01 Task 8: the filename-only size match is removed; image-variant matches are shown as estimates.
4. Plan 02 Task 1: the summary rules and thresholds (5 MB / 2 MB page weight, 50 / 80 header score, top five findings).
5. Plan 02 Task 4: batch defaults (clear site data on, 90 s timeout, 5 s linger, at most 50 sites, one zip with nested packages).
6. Plan 03: the app denies every camera, microphone and location request and records it.
7. Plan 04: fingerprinting is only checked in the separate fresh load, never in the live browser.
8. Plan 05: the Structure tab sits in the Code group before DOM Tree and is browser-only in its first version.
